# 06 技术框架与开发规范

## 要点速览

1. **双线程架构决定了很多"不能"**：小程序的逻辑层（跑 JS）和视图层（画界面）在不同线程，不能像网页那样直接操作 DOM，jQuery 一类库和部分 npm 包用不了；界面更新靠 setData 把数据从逻辑层发到视图层，发得多、发得勤就会卡 [3][4][93]。
2. **代码包硬上限**：主包、单个分包各 ≤2M，所有分包合计 ≤30M（服务商代开发的小程序 ≤20M）；tabBar 页面必须在主包；大图、视频等资源应放 CDN、用链接加载 [25][26][31]。
3. **基础库版本由用户的微信决定**，开发者不能指定。截至 2026-11-02，移动端 3.17.5 单版本占 88.79%，3.0.2 及以上合计约 99.3%；可在后台设"基础库最低版本"，低于它的用户打不开 [5][11][12]。
4. **Skyline 是可选的新渲染引擎**，官方数据称首屏比 WebView 快 66%。它可以按页面或分包开启，但有四个限制：Windows/Mac 端未支持；默认要经 We 分析 AB 实验放量；需要自己做导航栏；开发者工具的体验评分不支持它。商品平台宜在浏览类重页面试点，交易链路保持 WebView（推断）[17][18][19][20][38]。
5. **接口域名一律走白名单**：request、上传、下载、WebSocket 只能访问后台配置过、已 ICP 备案的 HTTPS/WSS 域名。web-view 内嵌网页另需配"业务域名"，个人主体小程序不能用 web-view [66][67][68]。
6. **后端有三条路**：
   - 自建服务器：最灵活；
   - 微信云开发：Serverless，现行"资源点"计费，1000 点 = 1 元，基础套餐 19.9 元/月含 4 万点；
   - 微信云托管：容器服务，基础资源只有按量计费（增值服务"出口固定 IP"例外，按月预付），用 callContainer 调用可免配服务器域名。

   多商家平台更适合自建或云托管（推断）[66][72][73][79]。
7. **框架**：只做微信小程序时，原生开发（可用 TS/Less/Sass）最稳；要同时出 H5、App 或其他平台小程序，再考虑 Taro（React 系）或 uni-app（Vue 系）。各框架"性能最好"的说法多为自述，Taro 官方文档自己承认重运行时有性能损耗 [43][49][50][54][57]。
8. **平台硬规则里最常踩的五条**：有账号体系必须提供微信授权登录和易找的"退出"；有账号或付费内容要给审核测试号；禁止音视频自动播放；弹窗必须能关；提审版本必须与线上一致 [1]。
9. **性能及格线**可直接用开发者工具"体验评分"的阈值：首屏 ≤5 秒、单次 setData ≤256KB、每秒 setData ≤20 次、页面节点 <1000 个、请求 1 秒内返回 [99]。
10. **安全底线**：
    - AppSecret 只放服务器，可开 IP 白名单，不用时冻结；
    - session_key 不下发前端；
    - 重要逻辑放后端，每个接口在后端鉴权；
    - 多商家平台要重点防"商家 A 操作商家 B 的订单"这类越权。

    [104][105][106]
11. **2025–2026 的主要变化**：开发者工具 2.02 改用 Electron 底座，并开放给 AI 编程 Agent 用的 Skills/MCP；官方推出"小程序 AI 开发模式"（内测中，暂不能提审）；云开发改为资源点计费；Skyline 和 glass-easel 持续迭代；分包上限未见调整 [25][33][35][73][112]。

> 阅读说明：本章只讲"技术怎么做、平台技术规则怎么守"。主体与备案见第 01 章，类目资质见第 02 章，支付见第 03 章，交易运营规则见第 04 章，建设路径见第 05 章，登录/手机号/隐私等开放能力见第 07 章，提审与运维见第 08 章，营销增长见第 09 章。
>

> - "（推断）"：基于官方事实给出的建议，不是官方原话；
> - "（第三方，未核实）"：未在官方原文核到的说法。

## 一、小程序是怎么跑起来的（架构速懂）

### 1.1 双线程：逻辑层 + 视图层

小程序框架分两层，层与层之间的数据传输和事件由框架负责 [4]：
- **逻辑层**（App Service）：运行 JavaScript，处理数据、请求和事件；
- **视图层**（View）：用 WXML/WXSS 描述并渲染界面。

这两层跑在不同线程上，带来三点影响：
- 网页里"脚本卡住、页面就失去响应"的问题被隔开了；
- 一个小程序有多个页面，视图层就有多个 WebView [3]；
- 逻辑层没有浏览器环境，**不能用 DOM/BOM API**，jQuery、Zepto 这类库跑不起来，部分依赖 Node 环境的 npm 包也不能用 [3]。

各端运行环境（WebView 渲染模式）[5]：

| 运行环境 | 逻辑层（JS 引擎） | 视图层（渲染引擎） |
|---|---|---|
| iOS / iPadOS / macOS | JavaScriptCore | WKWebView |
| Android | V8 | 微信 XWeb（基于 Mobile Chromium 内核） |
| Windows | Chromium 内核 | Chromium 内核 |
| HarmonyOS | V8 | ArkWeb（基础库 3.7.0 起正式支持）[24] |
| 开发者工具（仅调试） | NWJS 或 Electron | Chrome WebView |

对产品/策划的含义：
- iOS 的 JavaScriptCore 不能开 JIT（即时编译），同等条件下 JS 跑得比其他平台慢 [5]。优惠叠加、价格试算这类重计算建议放后端（推断）。
- 开发者工具只是模拟，最终以真机表现为准。测试要覆盖 iOS、Android，有需要再加鸿蒙和 PC [5]。

### 1.2 四类文件

一个页面（或自定义组件）由四个**同路径、同文件名**的文件组成 [6]：

| 文件 | 类比网页 | 作用 | 必需 |
|---|---|---|---|
| `.wxml` | HTML 模板 | 页面结构 | 是 |
| `.wxss` | CSS | 页面样式 | 否 |
| `.js` | JavaScript | 页面逻辑、数据、事件处理 | 是 |
| `.json` | 配置文件 | 标题栏、引用的组件等页面配置 | 否 |

整个小程序另有三份全局文件 [6]：
- `app.js`：必需；
- `app.json`：全局配置，必需，页面清单、分包、tabBar 都写在这里；
- `app.wxss`：全局样式，可选。

上传时，除被编译的文件外，只有白名单后缀（png、jpg、svg、json、mp3、mp4、wasm 等）的文件能进代码包 [6]。

### 1.3 页面、组件与生命周期

- **页面生命周期**：每个页面有一套固定的回调，依次是 `onLoad`（加载）→ `onShow`（显示）→ `onReady`（首次渲染完成）→ `onHide`（隐藏）→ `onUnload`（卸载）[7]。
- **自定义组件**：可复用的界面单元，如商品卡片、SKU 选择器、价格组件。
- **小程序整体的状态**：
  - 有冷启动和热启动之分；
  - 用户离开后小程序进入"后台"，约 **5 秒**后 JS 停止执行（挂起）；
  - 挂起超过 **30 分钟**会被销毁；iOS 内存告警时也可能被主动销毁 [8]。
  - 含义：下单页、长表单（如商家入驻）要考虑被销毁后的状态恢复（推断）。
- **后台网络请求**：进入后台后，5 秒内没结束的网络请求会失败（`fail interrupted`）[66]。
- **页面栈最多 10 层** [9]：
  - 商品详情 → 相似推荐 → 详情……连续跳转会触顶，要用重定向或控制层级（推断）；
  - 连续的 Skyline 页面之间跳转不受这个限制 [16]。

### 1.4 基础库：版本、覆盖率与"最低版本"

- **基础库是什么**：内嵌在微信客户端里的小程序运行时。用户用哪个版本，由他装的微信版本决定，开发者不能指定；新版本会静默、分批推送 [5][10]。
- **版本号规则**：`major.minor.patch` 中，前两位升级依赖客户端升级，第三位不依赖 [10]。
- **最新版本**：v3.17.6（2026-10-21）[13]。

各版本覆盖率（截至 2026-11-02，取自官方"基础库版本分布"页的数据接口，安卓 + iOS 合计口径）[11]：

| 基础库版本 | 该版本及以上合计占比 | 对应能力门槛（举例） |
|---|---|---|
| ≥3.17.5 | 89.49% | 当前主流版本（3.17.5 单独占 88.79%） |
| ≥3.11.3 | 96.36% | 鸿蒙端使用 Skyline 所需 [15] |
| ≥3.8.12 | 98.30% | WebView 下启用 glass-easel [23] |
| ≥3.0.2 | 99.26% | 安卓/iOS 端使用 Skyline [15] |
| ≥2.11.2 | 约 100% | 分包异步化、用时注入 [29][30] |

注：该接口没有给出 PC、Mac、鸿蒙端的分布；数据每天都在变。

**最低基础库版本设置** [12]：
- 位置：小程序后台「设置 - 基本设置 - 基础库最低版本设置」；配置前可看近 30 天访问用户的版本占比。
- 效果：版本低于设置值的用户**无法打开**小程序，会被提示升级微信。
- 代码层兼容：也可以用版本号比较、判断 API 是否存在、`wx.canIUse` 来兼容低版本。
- 体验评分会提醒"用到的 API 版本高于线上最低版本"，这一项不计分 [101]。

### 1.5 渲染引擎：WebView 与 Skyline

Skyline 是微信在 WebView 之外新增的渲染引擎：用一条独立的渲染线程负责布局和绘制，多个页面共享一个引擎实例，目标是体验更接近原生 App [14][16]。

| 维度 | WebView（默认） | Skyline |
|---|---|---|
| 原理 | 每个页面一个 WebView | 独立渲染线程，页面之间共享资源 [14] |
| 官方性能数据 | 基线 | 首屏时间快 66%（取官方"小程序助手"的线上数据，机型越低端差异越明显）；单页内存少 35%、两个页面少 50%（官方在本地测量，不是线上数据）[17] |
| 页面栈 | 最多 10 层 [9] | 连续 Skyline 页面跳转不受此限 [16] |
| 长列表 | 需自行做虚拟列表，可用官方扩展组件 recycle-view [96] | scroll-view 只渲染屏幕内的节点，并支持延迟挂载（lazy mount）[16] |
| 动效能力 | CSS 动画、WXS | 另有 Worklet 动画、手势系统、自定义路由、共享元素动画 [16] |
| 支持端 | 全平台 | 安卓/iOS 微信 8.0.40+（基础库 3.0.2+）、鸿蒙微信 1.0.10+（基础库 3.11.3+）[15]；**Windows/Mac 未支持（规划中）**，企业微信也未支持 [18][20] |
| 样式 | 完整 Web CSS | 只支持部分 WXSS 属性和取值（如 overflow 不支持 scroll、要改用 scroll-view；font-size 不支持百分比），节点默认 flex 布局 [120][18]；**不支持原生导航栏**，要自己做 [18] |
| 组件框架 | exparser 或 glass-easel | 只能用 glass-easel [23] |
| 上线方式 | 直接生效 | 默认受 We 分析 AB 实验控制，不配置的话线上仍是 WebView；AB 实验分到 100% 流量≠全量（实际是两种引擎各 50%）；可配 `disableABTest` 跳过实验 [15][19] |
| 工具支持 | 完整 | 体验评分不支持 Skyline [38]；热重载仍在开发 [20] |
| 不支持时 | — | 低版本微信和 PC 端自动降级为 WebView 渲染，需保证降级后显示正确 [15][19] |

**现状**：Skyline 引擎 2026 年持续迭代，从 1.4.15 更新到 1.4.24（2026-10-16）[21]；官方还发布了给 AI 编程工具用的"Skyline Skills" [22]。

**对商品平台的建议（推断）**：
- 适合试点 Skyline 的页面：首页信息流、分类页商品列表、商品详情的图片浏览、SKU 半屏弹层。这些页面浏览和交互都重，可按页面或分包开启 [16][18]。
- 继续用 WebView 的页面：下单、支付结果、订单、售后、商家工作台，减少兼容面。
- PC 端用户多（如企业采购）时，暂不依赖 Skyline 的特有能力 [20]。

### 1.6 glass-easel：新一代组件框架

- **定位**：替代旧组件框架 exparser 的新框架。Skyline 只支持 glass-easel；WebView 从基础库 **3.8.12** 起也可以用 [23]。
- **启用条件** [23]：
  - 先在 app.json 打开"按需注入"；
  - 页面配置里建议 `componentFramework: "glass-easel"` 与 `glassEaselWebview: true` **两项同时**配置；
  - 与旧框架有少量写法差异，比如模板转义规则变了，不再支持 `wx-if` 写法。
- **含义（推断）**：新项目一开始就按 glass-easel 的写法规范开发，日后局部迁到 Skyline 的成本更低。

## 二、代码包限制与分包策略

### 2.1 硬限制

| 项目 | 现行规则 | 出处 |
|---|---|---|
| 主包 | ≤2M | [25] |
| 单个分包 | ≤2M | [25] |
| 全部分包合计 | ≤30M；服务商代开发的小程序 ≤20M | [25] |
| tabBar 页面 | 必须放在主包 | [26] |
| 分包间引用 | 分包之间不能互相 require、引用模板和资源（用"分包异步化"时例外），分包可以引用主包 | [26] |
| 预下载额度 | 同一分包内的页面共享 2M 预下载额度；默认只在 Wi‑Fi 下预下载 | [28] |
| 包内资源 | 代码包下载时用 ZSTD 压缩，但图片、音视频、字体很难再压小 | [31] |
| npm | 只有构建产物目录计入包体；devDependencies 里的依赖不参与构建 | [42] |

说明：2025–2026 年没有看到包体上限调整的官方公告。分包文档最后编辑于 2026-06-16，数字仍是 30M/2M [25]。

### 2.2 分包与"注入"的六种手段

| 手段 | 一句话解释 | 适合场景 | 门槛与限制 |
|---|---|---|---|
| 普通分包 | 用户进入该分包的页面时才下载 | 大多数非首页功能 | 引用规则见上表 [26] |
| 独立分包 | 从该分包的页面进入小程序时，**不用下载主包** | 广告页、活动页、支付页（官方举例）[31] | 不能依赖主包和其他分包的代码、模板、样式、组件；`app.wxss` 对它无效；不能定义 App；暂不支持插件；`getApp()` 可能拿不到 [27] |
| 分包预下载 | 进入某个页面时，自动预下载接下来可能要去的分包 | 首页→商品详情、详情→下单 | 只能写配置，不能调 API；共享 2M 额度；默认仅 Wi‑Fi [28] |
| 分包异步化 | 跨分包的组件和 JS 可以异步加载，加载完之前先显示一个"占位组件" | 主包快满时，把大组件、插件挪出主包 | 基础库 2.11.2+ [29] |
| 按需注入 | 启动时只注入当前页面用到的代码 | 所有项目 | 基础库 2.11.1+；改配置后要全面回归测试 [30] |
| 用时注入 | 组件真正要渲染时才注入它的代码 | 首屏以外的重组件 | 基础库 2.11.2+，且要先开按需注入 [30] |

官方还有两条建议 [31]：
- 在 `app.json` 里全局引用的组件和插件会随启动一起注入，只在某个分包用的，就只在那个分包里引用；
- "小程序直播"这类低频插件建议放进分包。

### 2.3 图片等资源放 CDN

- **官方建议**：代码包里只放小图标；大图、音频、视频、字体部署到 CDN，用 URL 引入；也不要在 WXSS 里大量用 base64 内联图片 [31]。
- **图片尺寸与缓存**：
  - 图片按显示尺寸裁剪，体验评分的标准是"图片宽×高 ≤ 显示宽×高×像素比²"；
  - 开启 HTTP 缓存 [99]；
  - `image` 组件支持 WebP（需打开对应属性）和懒加载 [97]。
- **CDN 域名要不要配白名单**：
  - 需要配白名单的是 request、uploadFile、downloadFile、WebSocket 这几类网络接口 [66]；
  - `image` 组件直接加载 CDN 图片是否需要配域名，官方网络文档没有单列，据此推断不需要；开放社区里"社区技术运营专员"2020-11 曾回复"不需要"（社区页面抓取失败，未逐字核实）；
  - 但 HTTPS 证书要求同样适用于图片 [66]，建议真机验证。
    - 例外：`wx.getImageInfo` 处理网络图片时"需先配置download域名才能生效"[117]，`wx.downloadFile` 也只能访问已配置的 downloadFile 合法域名 [66]。商品分享海报、canvas 合成图片常用到这两个接口，所以 CDN 图片域名仍应加进 downloadFile 合法域名（推断）。

### 2.4 商品平台的分包方案（推断，供与研发讨论）

| 页面 | 建议位置 | 理由 |
|---|---|---|
| 首页、分类、购物车、个人中心 | 主包（作为 tabBar 页面） | tabBar 页面必须在主包 [26]；首页是启动页 |
| 搜索、搜索结果、商品详情、评价列表、店铺主页（多商家才有） | 分包 `goods`，在首页、分类页配置预下载 | 浏览主链路，首次进入要快 [28] |
| 确认订单（下单）、地址/优惠券选择、支付结果 | 分包 `trade`，由商品详情、购物车预下载 | 交易链路集中；支付结果页受运营规范 2.5.30、2.5.36 约束 [1] |
| 订单列表/详情、物流、售后申请/进度 | 分包 `order`，由个人中心预下载 | 中频访问 |
| 投放落地页、活动会场 | **独立分包** | 官方建议广告页、活动页放独立分包以加快启动 [31]；注意不能复用主包的代码和样式 [27] |
| 商家入驻、商家工作台（多商家才有） | 分包 `merchant`，不预下载 | 只有商家访问；表单和图片上传多 |
| 直播、富文本编辑器、图表等重组件或插件 | 放在用到的分包，配合分包异步化/用时注入 | 不拖慢首屏 [29][30][31] |

**自营商城与多商家平台的差别**：
- 自营商城页面少，上面四个分包通常就够；
- 多商家平台多出店铺页、商家入驻和商家工作台。商家端功能（商品发布、订单发货、售后处理、对账）往往很重，建议放独立分包，或另做"商家版"小程序/PC 后台（另做小程序涉及主体、类目、备案，见第 01、02 章）（推断）。

### 3.2 miniprogram-ci：上传与预览自动化

- **是什么**：从开发者工具里抽出来的编译与上传模块，不用打开工具（比如在 CI 流水线里）就能完成以下操作 [41]：
  - 上传代码、生成预览；
  - 构建 npm；
  - 上传云函数、云托管、云存储；
  - 获取最近上传版本的 sourceMap。
- **前置准备** [41]：
  - 在公众平台「管理 - 开发管理 - 开发设置 - 小程序代码上传」生成**代码上传密钥**；
  - 配置 **IP 白名单**（官方建议默认开启）；
  - 密钥不会明文保存在平台上，丢了只能重置。
- **其他**：上传时可用 `robot` 参数（取值 1~30）区分不同的 CI 机器人 [41]；npm 上 `latest` 标签的版本为 2.1.31（2026-03-12），`beta` 标签已到 2.1.48（2026-09-30）[59]。
- **建议（推断）**：CI 的出口 IP 固定后加进白名单；密钥放在 CI 的机密变量里，不进代码仓库。

### 3.3 npm、TypeScript、Less/Sass

- **npm** [42]：
  - 基础库 2.2.1+ 支持；
  - 安装后要在工具里执行"构建 npm"；
  - 只支持纯 JS 包，或专门为小程序发布的组件包；
  - 不支持依赖 Node 内置库或 C++ 扩展的包。
- **TypeScript / Less / Sass** [43]：
  - 开发者工具内置了编译插件，在 `project.config.json` 里开启 typescript、less、sass 即可；新建项目可直接选 TS 模板；
  - 注意：TS 编译只"去掉类型标注"，类型错误只在编辑器里提示，**编译时不报错**；
  - miniprogram-ci 1.6.1+ 也支持这些编译插件。

## 四、框架选型

### 4.1 原生 vs Taro vs uni-app vs Mpx

| 维度 | 原生开发 | Taro | uni-app | Mpx |
|---|---|---|---|---|
| 出品方 | 微信官方 | 京东凹凸实验室（O2Team）开源 [49][60] | DCloud（数字天堂）[54] | 滴滴 [57] |
| 写法 | WXML/WXSS/JS（可用 TS） | React / Vue / Preact 等 [49] | Vue [54] | 在小程序原生语法上增强，采用类 Vue 的单文件写法 [58] |
| 可输出的端 | 微信小程序；借"多端应用"出 iOS/Android/鸿蒙 App [61] | H5、React Native；微信、京东、百度、支付宝、抖音、QQ、钉钉、企业微信、飞书、快手等小程序；华为 ASCF 元服务 [49]；鸿蒙（4.1.0+）[53] | iOS、Android、鸿蒙 Next、Web；微信、支付宝、百度、抖音、飞书、QQ、快手、钉钉、淘宝、京东、小红书小程序；快应用、鸿蒙元服务 [54] | 各家小程序、Web、React Native [58] |
| 性能说法（均为框架自述） | 没有额外运行时 | 官方承认 Taro 3"重运行时、轻编译时"，性能有一定损耗；页面节点多时渲染性能会大幅下降，为此提供"半编译模式"（仅 React，用更大的包体换速度）[50][51] | 官网称"小程序端的性能优于市场其他框架"，页面没有给数据 [54] | 官网称性能与包体积"业内最优"，运行时约 51KB，没有附对比数据 [57][58] |
| 微信新能力跟进 | 最快 | 已支持 Skyline（仅微信；worklet 需 4.0.8+）[52] | 已支持微信 AI 开发模式：vue2 项目 5.14+，vue3 项目和 uni-app x 5.21+ [56] | 未核实 |
| 活跃度（2026-11） | — | 最新 4.3.2（2026-11-02 发布；上一版 4.3.1 为 2026-10-23）[59] | 2026-10 仍在发新版（latest 为 2026-10-23 的构建）[59] | latest 标签仍是 2.11.1（2026-07-22），beta 版到 2026-10 仍在发 [59] |
| 主要风险 | 只覆盖微信 | 跨大版本迁移有成本；运行时有开销 | 与 DCloud 工具链绑定较深，官网推荐使用 HBuilderX 编辑器 [54] | 社区规模较小 [60] |

**维护风险提醒**：同类框架 Remax 的仓库已归档、停止更新：主分支最后一次提交在 2022-08，最后一个正式版本 v2.15.14 发布于 2022-05；GitHub 上显示的 2024-03 是仓库最后一次推送时间，不是主分支提交 [60]。选第三方框架前，要看三件事：最近的版本时间、issue 处理情况、团队在必要时能否"降级回原生"（推断）。

**怎么选（推断）**：
- **只做微信小程序**（多数自营商城）：原生 + TypeScript。UI 组件可选官方 WeUI，或腾讯开源的 TDesign、有赞开源的 Vant Weapp（第三方组件库，本报告未做评测）[60]。
- **同时要上抖音、支付宝等小程序或出 H5**：团队熟 React 选 Taro，熟 Vue 选 uni-app。
- **要出 App**，三条路：
  - 微信"多端应用"，复用微信小程序代码（见 4.2）；
  - uni-app / uni-app x，App 端原生渲染 [55]；
  - Taro 的 React Native 方案。
- **多商家平台**：买家端小程序和商家端可以用不同技术栈；商家 PC 后台用常规 Web 技术栈，与小程序框架无关。

### 4.2 微信"多端应用"（Donut）

- **是什么**：用小程序代码和微信开发者工具构建 Android、iOS、HarmonyOS App，支持条件编译。原生开发的小程序和用第三方框架开发的小程序都能构建 [61]。
- **收费**：
  - 开发、编译、调试、预览等基础功能"永久免费"；
  - 云构建安装包有免费次数，例如每位开发者每个自然周可免费构建 APK 50 次，只改了小程序代码的构建不消耗次数 [61][63]；
  - "专业版"在公测期可免费升级，但只面向**已上架**、且基于多端框架开发的 App；升级后会去掉底部的"Powered By Donut"水印等 [62]；
  - 专业版的正式价格尚未公布。
- **现状**：原文档站 dev.weixin.qq.com/docs/framework 已停止维护，文档迁到了微信文档中心 [65][61]。
- **注意**：App 里的微信支付不能直接沿用 `wx.requestPayment`，要改用 `wx.miniapp.requestPayment`，走的是 App 支付（第 03 章只讲小程序支付，没有展开 App 支付，前置条件见下一句）[64]。前置条件是在微信开放平台申请移动应用账号、在微信商户平台创建商户号，并把两者绑定；这个接口的签名只支持 V3，要配合 V3 下单接口使用 [118]。适配文档还提示部分 iOS 场景要用苹果内购 IAP [64]，实物商品一般不涉及（推断）。

## 五、后端选型

### 5.1 自建服务器：服务器域名规则

| 规则 | 内容 | 出处 |
|---|---|---|
| 适用接口 | `wx.request`、`wx.uploadFile`、`wx.downloadFile`、`wx.connectSocket` 只能访问事先配置好的域名 | [66] |
| 配置位置 | 小程序后台「开发管理 - 开发设置 - 服务器域名」 | [66] |
| 协议 | 请求、上传、下载只支持 https；WebSocket 只支持 wss | [66] |
| 地址 | 不能用 IP 地址（小程序局域网能力除外）或 localhost；不能用父域名代替子域名 | [66] |
| 端口 | https 域名配了端口就只能请求该端口；没配端口时 URL 里不能带端口（包括 443）；wss 不用配端口 | [66] |
| 备案 | 域名必须完成 ICP 备案（见第 01 章） | [66] |
| 禁止项 | `api.weixin.qq.com` 不能配为服务器域名，相关接口不能在小程序里直接调用 | [66] |
| 数量与修改次数 | 第三方平台代配置接口的规则：每类域名最多 200 个，每月可提交修改申请 50 次；直接在后台修改的次数，现行文档没写（见待确认） | [69] |
| DNS 预解析 | 最多 5 个域名 | [66] |
| HTTPS 证书 | 有效、受系统信任、与域名一致、在有效期内、信任链完整；TLS 1.2+；iOS 不支持自签名证书，且需满足苹果 ATS 要求 | [66] |
| 并发与超时 | 请求、上传、下载最多 10 个并发，WebSocket 最多 5 个；默认超时 60 秒 | [66] |
| 调试陷阱 | 工具里"不校验合法域名"的选项会掩盖配置错误；域名配好后应关闭它，并在各平台真机测试 | [66] |

**业务域名（web-view 用）**：
- 个人主体的小程序不能使用 web-view [67][68]；
- 每个小程序最多配 300 个业务域名 [67][70]，每个域名最多被 100 个主体的小程序绑定 [67]；
- 只支持 https；需 ICP 备案，新备案的域名 24 小时后才能配；配好后可打开它任意合法的子域名 [67]；
- 配置时要把平台给的校验文件放到域名根目录 [71]；
- 网页里 iframe 引用的域名也要配；每个页面只能有一个 web-view，它会铺满整个页面 [68]。

### 5.2 微信云开发

**是什么**：微信与腾讯云联合推出的 Serverless 服务，不用自己搭服务器 [72]：
- 能力包括文档型数据库、云函数、云存储（自带 CDN）、静态网站托管、CMS 等；
- 在云函数里可以免鉴权识别用户身份，免 access_token 调用微信开放接口，免签名调用微信支付。

**计费（现行）**：统一采用"资源点"计费，1000 资源点 = 1 元，各项资源按用量折算扣点；不能再切回旧的固定配额套餐 [73]。

| 项目 | 价格 |
|---|---|
| 基础套餐 | 19.9 元/月（原价 39 元），含 40,000 点/月；超出部分可加购资源包或开按量计费 [73] |
| 数据库调用 / 容量 | 0.2 元/万次；0.04 元/GB/天 [73] |
| 云函数调用 / 资源使用量 / 外网出流量 | 0.0133 元/万次；0.00011108 元/GBs；0.8 元/GB [73] |
| 云存储容量 / CDN 流量 | 0.00394 元/GB/天；0.21 元/GB [73] |
| 短信 | 0.05 元/条 [73] |

**免费环境** [73]：
- 没有云环境（或已注销超过 1 个月）的小程序，可以建一个免费环境；
- 小程序**未发布**期间免费；**发布后第 15 天到期**，要长期使用必须转为付费；
- 该活动截止到 2026-12-31。
- 官方价格计算器另写着"每月 40,000 点、可体验 6 个月"，两处说法不一致，见待确认 [75]。

**到期风险**：
- 旧版固定配额文档写明：套餐到期 7 天后仍未续费，第 8 天开始释放资源，数据不可恢复 [74]；
- 资源点模式下是否同样处理，现行文档没写。上线前务必设好续费和余额提醒（推断）。

**腾讯云侧的其他档位**：腾讯云 CloudBase 文档另列有标准版 199 元/月（33 万点）、企业版 999 元/月（150 万点）等档位，并称 MySQL 自 2026-10-20 起不再支持新开通 [76]。微信侧文档只列了基础套餐，小程序能否直接选这些档位，待确认。

### 5.3 微信云托管

**是什么**：容器化的后端托管服务 [77]：
- 支持大多数语言和框架，现有服务器上的服务可以平滑迁入；
- 自动扩缩容；
- 可免鉴权获取用户身份，免密调用微信开放接口和微信支付；
- 服务端接口可以设为禁止公网访问，只接受客户端经微信专线发来的请求。官方称这样"从根本上杜绝 DDoS 可能且无需支付额外费用"[77]，这是架构上的隔离，不是一项单独的 DDoS 防护产品（推断）。

小程序通过 `callContainer` 走微信私有链路调用云托管服务，**不用配置服务器域名** [66]。

**计费**：基础资源（CPU、内存、构建、公网流量、MySQL、对象存储等）只有按量计费，每日结算、次日扣费，需要先在腾讯云账户预充值；首个环境赠送 3 个月免费额度 [78][79]。例外是增值服务"出口固定 IP"：包年包月、先付后用，49 元/（月·环境），购买后不支持退款；官方说明它可用作调用外部接口时的允许访问 IP（举例有政企接口、微信支付提现到零钱接口），但不能用于域名备案 [79]。商品平台对接要求固定 IP 的支付、ERP、物流接口时会用到（推断）。

| 计费项 | 单价 | 首个环境免费额度（3 个月有效） |
|---|---|---|
| CPU | 0.055 元/核·小时 | 720 核·小时 |
| 内存 | 0.032 元/GB·小时 | 1440 GB·小时 |
| 构建 | 0.05 元/分钟 | 600 分钟 |
| 公网流量 | 0.8 元/GB | 5GB |
| MySQL 算力 / 存储 | 0.342 元/个·小时；0.00485 元/GB·小时 | 720 个·小时；720 GB·小时 |
| 对象存储容量 / CDN 流量 | 0.0043 元/GB·天；0.18 元/GB | 5GB；3GB |

以上为官方刊例价 [79]。按刊例价自行估算（推断）：一个 0.5 核、1GB 内存的实例全天候运行一个月，约 0.5 × 0.055 × 720 + 1 × 0.032 × 720 ≈ 43 元；不含数据库和流量，也没扣免费额度。

**欠费规则** [80]：
- 欠费 12 小时内：正常使用；
- 欠费 12 小时~7 天：**所有环境停服**，数据保留；
- 欠费超过 7 天：**资源销毁、无法找回**。

### 5.4 三者怎么选

| 维度 | 自建服务器 | 微信云开发 | 微信云托管 |
|---|---|---|---|
| 形态 | 自己的云服务器或容器集群 | Serverless：云函数 + 文档数据库 + 存储 | 容器托管 |
| 域名与备案 | 需备案域名、HTTPS 证书，并在后台配置 [66] | 小程序端直接调用，不用配服务器域名（推断） | 用 `callContainer` 调用时免配 [66]；给 PC 后台或 H5 用仍需域名 |
| 微信能力 | 自己管理 access_token 和签名 | 免鉴权、云调用、在云函数里调支付 [72] | 免鉴权、开放接口免密中转、支付 [77] |
| 费用 | 服务器 + 带宽 + 运维人力 | 19.9 元/月起，超出另计 [73] | 基础资源按量计费、需预充值；出口固定 IP 增值服务 49 元/月/环境预付 [78][79] |
| 适合 | 多商家平台；要对接 ERP、仓储、财务；多端共用后端 | 自营商城 MVP、活动页 | 想要传统后端架构但不想自己运维 |
| 主要风险 | 运维和安全全靠自己 | 用文档型数据库做复杂对账、报表较吃力（推断）；套餐到期会释放数据 [74] | 欠费超过 7 天资源销毁 [80] |

**自营商城与多商家平台**（推断）：
- 自营商城订单量不大时，云开发起步最快；
- 多商家平台涉及多租户数据隔离、分账结算（见第 03 章）、商家后台和开放接口，通常选自建或云托管。商家 PC 后台一定需要一个备案域名。

## 六、平台技术规范硬要求（运营规范 2.8 / 2.11 / 2.12 / 2.13）

以下按《微信小程序平台运营规范》（最后编辑于 2026-10-30）的条文意译 [1]，原文以官方页面为准。

### 6.1 2.8 内嵌网页（web-view）规范

| 条款要点 | 对商品平台的影响 |
|---|---|
| ① 内嵌网页必须已完成备案 | H5 域名同样要 ICP 备案，并配置为业务域名 [67] |
| ② 网页提供的服务须与小程序填写的类目、标签一致，不能超出平台类目库范围 | 用 H5 承载的会场、店铺页，也必须在已申请的类目内（类目见第 02 章） |
| ③ 网页内容须遵守《微信外部链接内容管理规范》 | 活动 H5 的文案同样受内容规范约束 |
| ④ 不得用内嵌网页绕开或规避平台规则 | 不能把审核不允许的功能放进 H5 |
| ⑤ 违规可被限制功能直至封禁，平台可拒绝再为该主体服务 | — |

**个人主体能否用 web-view**：不能 [67][68]。

**能不能用 web-view 承载主要功能**：
- 现行运营规范和《常见拒绝情形》里，没有一条明文禁止 [1][2]；
- 但运营规范 2.5.29 把"无实质服务内容"的小程序列为违规，可被下架或封号 [1]。其中与导流有关的情形有三种：靠扫码、点击跳转引导到其他小程序、公众号、加群；靠客服消息引导到公众号、H5 页面；靠页面提示引导下载 App 或加好友 [1]。这条没有直接禁止 web-view，但核心功能都放进 H5、小程序本身只剩一层壳，有被认定为"无实质服务"的风险（推断）；
- web-view 网页只能用清单内的少量 JSSDK 接口，清单里没有支付接口 [68]，所以网页里无法直接拉起小程序支付，要跳回小程序原生页面（推断）。

结论（推断）：首页、商品、购物车、下单、支付、订单这些核心链路用原生页面；H5 只做活动、协议说明等辅助页面。

### 6.2 2.11 可用性和完整性规范

1. 提交的必须是能打开、能运行的完成品，不能是测试版。→ 不要提交带"敬请期待"空页面的版本。
2. 不能导致微信客户端或小程序自身崩溃。
3. 不能有严重 Bug，比如无法打开、无法返回或退出、严重卡顿。
4. 已发布的小程序要保持流畅、稳定、安全；因自身原因导致服务中断、且没在合理期限内修复的，腾讯可以临时封禁等。→ 后端宕机、云环境到期或欠费停服都可能触发（推断）。
5. 有账号体系或付费内容时，要提供测试号（含账号和密码），让审核人员能体验全部功能。→ 多商家平台要准备"测试商家账号"，让审核也能看到商家工作台（推断）。

### 6.3 2.12 技术实现规范

1. 遵守开发文档和开发规范。
2. 允许并授权微信团队对代码和服务端后台做安全测试。
3. 系统安全：
   - 严禁利用手机系统、微信或其他软硬件的漏洞，一经发现回收主体的账号资格；
   - 不得运行有数据、交易、内容安全风险的代码；
   - 不得传播病毒。
4. API 使用：
   - 不得使用非公开 API；内测中的 API 微信有权回收；
   - 禁止违规跨主体使用其他第三方应用的 API；
   - 未经允许，不得出售、转让、转授微信的代码、API 或工具；
   - 不得修改、转译、逆向工程任何 SDK 或组件。
5. 其他要求：
   - 后台运行只限 VoIP、音频播放、地理位置、完成任务、本地提醒等用途；
   - 不得改变原生界面元素和行为；
   - **禁止视频、音乐、语音等多媒体自动播放**；
   - 不得在用户不知情时录音。
   - → 商品主图视频、直播预告不要默认自动播放。
6. 授权登录：
   - **有账号体系就必须提供微信授权登录**；
   - 用户拒绝授权后，可以在他表现出授权意向时再提醒；
   - **必须提供功能正常、容易找到的"退出"选项**；
   - 用户拒绝授权后，要清除并不再使用他的头像、昵称。
   - 登录与手机号的细节见第 07 章。
7. 文件上传下载：
   - 上传文件要明确提示用户，不得重复上传同一个文件；
   - 移动网络下，不得在用户不知情时大量下载文件。
   - → 商家上传商品图、用户晒单时都要有明确提示。
8. 模板消息：不得诱导用户触发、骚扰或营销。模板消息已被订阅消息取代，订阅消息规则见第 07、09 章。

### 6.4 2.13 小程序 UI 规范

1. 符合《微信小程序设计规范》（见第七节）。
2. 不得提供改变微信外观和功能的体验。
3. 图片和文字要简洁，不要用文字遮挡图片。→ 促销 Banner 不要满屏堆字。
4. 图标建议用有色背景。
5. **页面内的浮层和弹窗必须能关闭**。→ 首页优惠券弹窗、新人礼包浮层都要有关闭按钮。
6. 不得模仿系统通知或警告来诱导点击。
7. 页面下拉时，账号名称（即小程序名称）必须清晰可见，不能用背景色遮挡（原文说的是"账号字样""账号名称"）。

### 6.5 其他与技术实现直接相关的条款

| 条款 | 要点 | 技术含义 |
|---|---|---|
| 运营规范 2.5.19 | 提审版本必须与实际上线运营的版本一致；禁止用截屏、IP、地域、人群等手段对抗审核 [1] | 不要用远程开关在审核期间隐藏功能 |
| 运营规范 2.5.30 | 支付完成后的跳转页，不得跳到与业务无关的公众号文章，不得夸大误导；违规后只能跳回首页 [1] | 支付结果页的推荐位要克制 |
| 运营规范 2.5.36 | 不得拦截用户返回；支付等操作完成后，不得未经明确提示就弹出或自动跳到营销页 [1] | 返回键和支付回调的逻辑要合规 |
| 常见拒绝 3.1.2 | 从首页必须能直达、或最多点两次到达所有已申请类目的页面 [2] | 信息架构要满足"两次点击可达" |
| 常见拒绝 3.5.3 / 3.5.4 | 安装或运行其他可执行代码、违规加载或更新代码，都会被拒 [2] | 不要做"远程下发脚本"式的热更新 |

## 七、设计规范

### 7.1 《微信小程序设计指南》要点 [81]

| 主题 | 要点 |
|---|---|
| 导航 | 微信不提供统一的导航栏样式；建议次级页面左上角提供返回；iOS 可右滑返回，安卓可用返回键 |
| 右上角胶囊按钮 | 所有页面（包括内嵌网页、插件）右上角都有官方菜单控件，内容不能自定义，只能选深色或浅色；设计时要预留这块区域，附近放可点击元素要防冲突 [81]；开启自定义导航栏（`navigationStyle: custom`）后也只保留胶囊 [83]；胶囊的位置可用 `wx.getMenuButtonBoundingClientRect` 获取 [82] |
| 标签栏（Tab） | 2~5 个，建议不超过 4 个；一个页面只能有一组；微信原生底部标签栏只供首页使用 [81]；`app.json` 的 tabBar 同样限 2~5 项 [83] |
| 加载 | 启动页由微信统一提供；下拉刷新用标准能力；推荐局部加载反馈，慎用全屏的模态加载；加载要有动画，耗时长时要能取消；同一页面不超过一个加载动画 |
| 结果反馈 | 图标型、文字型的轻提示 1.5 秒后自动消失，不适合用来提示错误；需要用户明确知道的结果，用模态对话框或结果页 |
| 异常 | 出现异常要告诉用户原因和出路，不能让用户停在"死页面"；表单出错要标出出错字段 |
| 输入 | 尽量少让用户打字，多用选择项和接口能力（如扫码、地址、定位） |
| 点击区域 | 适宜点击的物理尺寸约 7mm–9mm；体验评分要求可点击元素宽高都不小于 20px [100] |
| 字体与设计稿 | 常用字号 22、17、15、14、12 pt；设计稿可用 375px 基准（固定布局、按比例缩放）或 390px 基准（响应式布局） |

### 7.2 适老化、无障碍、深色模式

- **适老化**（建议性）[84]：
  - 官方建议按用户的微信字体大小设置做适配；
  - 可用 `wx.getAppBaseInfo` 读取字体大小和缩放倍率（官方推荐用它；`wx.getSystemInfo` 自基础库 2.20.1 起停止维护，应改用 getAppBaseInfo、getDeviceInfo、getWindowInfo 等 [84][119]）；
  - iOS 有 7 档、安卓有 8 档字号，其中一档是"关怀模式"字号；
  - 界面元素应随字号档位一起放大。
- **无障碍**（建议性）：微信自己绘制的界面（如弹窗、导航栏）已内置无障碍特性，自己做的界面可以加 aria 无障碍属性 [85]；开发者工具有"无障碍访问模式"插件，可用来走查 [86]。
- **深色模式**（可选）[87]：
  - 在 `app.json` 里设置 `darkmode: true`；
  - 用 `theme.json` 定义浅色、深色两套变量，覆盖导航栏、tabBar 的颜色和图标等；
  - 基础库 2.11.0+ 支持。
  - 鸿蒙端暂不支持暗黑模式 [24]。

### 7.3 PC 端与平板

- **默认表现**：
  - PC 端（Windows、Mac）**不用特殊适配就能运行**小程序 [89]；
  - 但没做大屏适配时，竖屏小程序无论屏幕多大，都固定按 414×736 显示 [88]。
- **大屏适配方式** [89]：
  - 在 `app.json` 里配置 `resizable` 开启大屏适配，并用 `wx.onWindowResize` 响应窗口变化；
  - PC 端开启了大屏适配的小程序不支持自定义导航栏；
  - 没适配的小程序，窗口拉伸超过 1.5 倍时，框架会自动把页面分成左右两栏显示。
- **设计建议**：推荐用栅格系统加响应式策略；电商类可用"横向拓展"布局，宽屏时一行放更多商品 [88]。体验评分里"窗口变化适配"一项占 3 分权重 [100]。
- **Skyline**：不支持 PC 端，PC 上会回退到 WebView [15][20]。
- **建议（推断）**：消费类商城可以把 PC 适配往后放；企业采购、批发类平台的 PC 用户比例高，建议做大屏适配。

## 八、性能与体验

### 8.1 启动性能

- **定义**：从"用户打开小程序"到"首页渲染完成"（首个页面触发 `onReady`）[90]。
- **启动包含的环节**：运行环境准备、小程序信息准备、代码包下载、代码注入、首屏渲染等；其中开发者能优化的是代码包、代码注入、首屏渲染三块 [90][91]。

官方建议的启动耗时控制线 [90]：

| 场景 | 安卓 | iOS |
|---|---|---|
| 需要下载或更新代码包 | 3.7 秒 | 1.8 秒 |
| 使用本地代码包 | 2.6 秒 | 0.9 秒 |
| 大盘平均 | 3.0 秒 | 1.2 秒 |

关键的优化手段：
1. 分包。官方称这是优化启动耗时"效果最明显"的手段 [31]。
2. 开启按需注入、用时注入 [30]。
3. 开启"初始渲染缓存"（基础库 2.11.1+）：非首次启动时，先把上次的渲染结果展示给用户 [92]。
4. 首屏数据在 `onLoad` 或更早发起请求；还可以用"数据预拉取""周期性更新"提前取数 [92]。
5. 先用本地缓存的数据渲染，网络数据回来后再更新 [92]。
6. 数据没回来时，用骨架屏代替白屏 [92]。
7. 去掉没用到的全局组件和插件 [31]。

### 8.2 setData 使用规范 [93]

- `data` 里只放界面渲染要用的数据，其他数据挂在 `this` 的其他字段上；
- 只传发生变化的字段，不要用 `this.setData(this.data)` 整体传；
- 连续的更新尽量合并，不要在滚动回调里每次都 setData；
- 秒杀倒计时这类避免不了的高频更新，封装成小组件，在组件内部更新；
- 页面切到后台后，停止倒计时等高频更新。

### 8.3 长列表与图片

- **长列表**：
  - WebView 下可用官方扩展组件 recycle-view，只渲染屏幕内的数据 [96]；Skyline 下 scroll-view 自带按需渲染 [16]；
  - 单页 WXML 节点应少于 1000 个，节点树深度少于 30 层 [94]；
  - 商品曝光统计用 `IntersectionObserver`，不要在 `onPageScroll` 里反复查询节点位置 [94]。
- **图片**：
  - 按显示尺寸提供图片。大图、长列表里的大量图片会让 iOS 回收 WebView，导致白屏，严重时微信会强制关闭小程序 [95]；
  - Banner、背景图要预先指定尺寸，避免滥用 `widthFix`/`heightFix` 模式 [95]；
  - 开启 HTTP 缓存 [99]。

体验评分是开发者工具里的技术评分，与第 04 章的"交易体验分"不是一回事。它按规则逐条判定得分或不得分，再按权重算出总分 [98]：

| 类别 | 规则 | 权重 | 得分条件 |
|---|---|---|---|

| 体验 | 开启惯性滚动 / 不用 `:active` 做点击态 | 8 / 8 | iOS 上的滚动区域设置惯性滚动 / 改用 `hover-class` [100] |

## 九、安全指引

### 9.1 官方的五条开发原则 [104]

1. 不信任用户提交的数据（包括第三方系统提供的数据），必要的校验放在后台；
2. 最小权限：代码、模块只拥有完成任务所需的最小权限；
3. 禁止明文保存用户敏感数据；
4. 小程序前端代码（云函数除外）可以被外部获取并反混淆，重要业务逻辑要放在后台或云函数里；
5. 后台接口和云函数的调用，必须做有效的身份鉴权。

### 9.2 AppSecret 与 access_token

- **AppSecret 不能进前端**：
  - AppSecret（小程序的"开发者密码"）属于敏感信息，不能以明文、注释、base64、MD5/SHA1 等任何形式出现在小程序代码里 [104]；
  - `api.weixin.qq.com` 不能配为服务器域名，需要 AppSecret 的接口只能由服务器调用 [66]。
- **AppSecret 的管理** [106]：
  - 在公众平台「管理 - 开发管理 - 开发设置」可以启用、重置、冻结、解冻；
  - 可开启 **API IP 白名单**，开启后只有白名单内的 IP 能调用带 AppSecret 的接口；
  - 长期不用可以冻结。冻结后用它获取 access_token 会返回错误码 40243，但不影响云开发和第三方平台的调用。
- **access_token**：有效期 2 小时，重复获取会让上一个失效；官方建议用一台"中控服务器"统一获取和刷新，其他服务器都从它这里取；官方还推荐改用"获取稳定版接口调用凭据"接口（getStableAccessToken）[106]。

### 9.3 session_key 与敏感数据

- **session_key**：用户登录时，服务器用临时 code 换取 openid 和会话密钥 session_key。session_key 用于用户数据的加密签名，**服务器不应把它下发到小程序，也不应对外提供** [105]。
- **展示脱敏**（官方示例）[104]：
  - 手机号只显示前三位和后两位；
  - 银行卡只显示后 4 位；
  - 身份证只显示第一位和最后一位。
- **泄露后果**：存在敏感信息泄露问题的小程序，可能被下架并暂停相关服务 [104]。
- **加密手段**：
  - 本地缓存可在异步接口里开启 `encrypt` 加密存储（AES128）；本地缓存单个 key 上限 1MB，总上限 10MB [103]；
  - 服务端调用微信接口时，可配置签名（RSA/SM2）和报文加密（AES256/SM4）[107]。

### 9.4 接口鉴权（多商家平台的重点）

- **两类越权** [104]：
  - 平行越权：同一角色之间越权。比如用户 A 改个参数，就能看到用户 B 的信息。
  - 垂直越权：低权限角色调用了高权限接口。比如普通用户调到了管理员才能用的接口。
- **鉴权必须在后台做**：校验 openid、登录态、角色等，不能靠前端隐藏页面或按钮来代替 [104]。
- **多商家平台要额外保证**（推断）：
  - 商家只能读写本店的商品、订单、售后和资金数据；
  - 平台运营后台与商家后台分级授权；
  - 改价、退款、提现等关键操作留审计日志并做二次验证。官方也建议敏感服务增加短信、邮箱等二次验证 [104]。

### 9.5 防刷与风控

- **条件竞争**：攻击者用并发请求重复领奖、领券 [104]。优惠券、秒杀、积分、库存扣减这些接口要做幂等和加锁（推断）。
- **安全风控接口 `getUserRiskRank`**：
  - 按场景返回用户的风险等级，场景 0 为注册、1 为营销作弊、2 为 UGC；只能在服务端调用 [109]；
  - 官方给了按等级处置的建议（风险等级 0~4，数字越大风险越高）：0 级不拦截；1~2 级加验证码或短信等简单验证；3 级按业务场景采取措施，比如营销活动降低高等级奖励的概率；4 级建议直接拦截，比如红包活动返回不中奖或最小额红包 [108][109]；
  - 开通入口：「开发管理 - 安全中心 - 用户风控 - 安全风控接口」[108]。
- **内容安全**：运营规范 2.10 要求有过滤违规内容的机制 [1]。

  | 接口 | 用途 | 调用上限与限制 |
  |---|---|---|
  | `msgSecCheck` | 文本检测 | 4000 次/分钟、200 万次/天；未上架的小程序 100 次/天；被检测的用户也须在近两小时内访问过小程序 [110] |
  | `mediaCheckAsync` | 图片、音频异步检测 | 2000 次/分钟、20 万次/天；单文件不超过 10M；结果在 30 分钟内推送；被检测的用户须在近两小时内访问过小程序 [111] |

  官方列举的应用场景里就有"电商类商品上架图片检测"[111]。多商家平台的商家商品图、详情文案，以及用户的评价晒图，都应该过检（推断）。

### 9.6 代码保护

- 上传时可开"压缩代码"（压缩并混淆 JS）和"代码保护"（把文件扁平化、替换 require 引用的文件名；部分写法不适用）[44]；
- 官方"代码加固"插件对 JS 做字符串加密、调用转换、代码混淆等；加固后的报错可以用 sourcemap 工具反查 [45]；
- 加固只是提高破解门槛，官方原则仍是关键逻辑放后端 [104]。

### 9.7 服务端常见漏洞

官方安全指引列出的服务端常见漏洞及对策 [104]：
- SQL 注入：用参数化查询；
- 命令注入：过滤或转义用户输入；
- 弱口令：禁用默认账号，加二次验证；
- 文件上传：用白名单校验文件类型；
- 文件下载、目录遍历：限制可访问的目录范围，按文件 id 取文件；
- 条件竞争：见 9.5。

## 常见坑与驳回原因

1. **主包超过 2M，上传失败**：通常是图片、字体打进了主包，或该放 devDependencies 的依赖放在了 dependencies 里。对策：资源放 CDN、按功能分包、测试依赖移到 devDependencies [25][31][42]。
2. **把 tabBar 页面放进了分包**：不允许 [26]。
3. **独立分包里用了主包的公共组件、全局样式或 `getApp()`**：独立分包不能依赖主包内容 [27]。
4. **"开发者工具里能请求，手机上不行"**：常见原因有四个——没配服务器域名、证书链不完整、TLS 版本过低、开发时勾了"不校验合法域名" [66]。
5. **web-view 白屏**：常见原因是没配业务域名、没放校验文件、iframe 引用的域名没配，或者个人主体用了 web-view [67][68][71]。
6. **页面栈满 10 层后跳转失败**：典型场景是详情页的无限推荐链 [9]。
7. **setData 太大、太频繁导致卡顿**：单次超过 256KB、每秒超过 20 次 [99][93]。
8. **审核被拒或被判违规的常见技术原因** [1][2]（《常见拒绝情形》里的对应条款：3.3.4 测试号、3.5.2 多媒体自动播放、3.5.5 "退出"选项、3.6.2 浮层和弹窗可关闭）：
   - 有账号体系却没有微信登录或"退出"入口；
   - 没给测试账号；
   - 音视频自动播放；
   - 弹窗关不掉；
   - 拦截返回；
   - 支付完成后自动跳到营销页；
   - 提审版本与线上版本不一致。
9. **从首页点两次到不了某个已申请类目的页面**，因此被拒 [2]。
10. **"热更新"式远程下发代码**：违规加载或更新代码会被拒 [2]。
11. **Skyline 上线后，用户实际仍在用 WebView**：原因是没配 We 分析 AB 实验、也没设 `disableABTest`；或者误以为 AB 实验 100% 就是全量 [15][19]。
12. **Skyline 页面顶部的导航栏消失了**：Skyline 不支持原生导航栏，要自己做 [18]。
13. **用体验评分测 Skyline 页面**：不支持 [38]。
14. **云环境"突然没了"**：免费环境在发布后第 15 天到期；固定配额套餐到期 7 天后释放数据；云托管欠费超过 7 天资源销毁 [73][74][80]。
15. **安全上的三个典型错误**：把 AppSecret 写进小程序代码、把 session_key 下发前端、只在前端隐藏按钮来做权限。这些都是安全指引明确反对的做法 [104][105]。
16. **把 AI 开发模式的代码合入正式版提审**：官方明确要求不要这样做 [112]。
17. **鸿蒙端功能缺失**：暗黑模式、分享朋友圈、初始渲染缓存、广告组件等暂不支持，要做兼容判断 [24]。

## 待确认 / 存疑

1. **服务器域名每月能改几次**：
   - 现行网络文档没写；
   - 第三方平台接口文档写的是"每类最多 200 个、每月可提交修改申请 50 次"[69]；
   - 早年社区里有官方回复称后台每月限 5 次（第三方说法；社区页面抓取失败，未核实）。
   - 以后台页面的实际提示为准。
2. **Skyline 的最低版本**：起步页写安卓/iOS 微信 8.0.40+（基础库 3.0.2+）[15]，兼容页写安卓 8.0.33+、iOS 8.0.34+ [18]，两页不一致（2026-11-02 复核仍不一致）。工程上按更严格的基础库 3.0.2+ 判断即可，这部分用户已占约 99.26% [11]（推断）。
3. **Skyline 是否支持鸿蒙**：起步页列出鸿蒙微信 1.0.10+（基础库 3.11.3+）可用 [15]，但鸿蒙适配指南（2026-09-01 版）写 Skyline"暂未提供"[24]。倾向以起步页为准：Skyline 更新日志 2025-04-08（1.4.6）就记了"新增 HarmonyOS 支持"，2026 年还有"鸿蒙 skyline 内存占用优化"等条目 [21]，基础库 3.12.1 也修过 ohos skyline 的问题 [13]，适配指南很可能没更新（推断）。同一份指南写鸿蒙端"暗黑模式不支持"，也和 Skyline 1.4.7"HarmonyOS 下支持暗黑模式"对不上 [21][24]。鸿蒙端上线前仍要真机验证。
4. **Skyline 对企业微信的支持状态**：状态页写"规划中"[20]，兼容页写"开发中"[18]。
5. **体验评分的规则数**：原文称 27 条，权重表实际列了 28 行 [98]。
6. **云开发免费环境的口径**，三处说法不同：
   - 计费说明写"未发布期间免费、发布后第 15 天到期"[73]；
   - 价格计算器写"每月 40,000 点，可体验 6 个月"[75]；
   - 腾讯云文档写免费体验版每月 3,000 点 [76]；但该页同时写明续期政策"仅适用于云开发控制台创建的体验版环境（微信体验版不适用）"，可见 3,000 点指腾讯云控制台创建的环境，和小程序侧的免费云环境不是一回事（推断）。
7. **云开发资源点计费的生效日期**：没找到官方公告。资源点模式下到期、欠费、数据释放的规则，现行文档也没写明；旧文档的规则是到期后第 8 天释放 [74]。2026-11-02 复核：固定配额计费页只写已"统一调整为资源点计费模式"，没有日期；《资源超限和到期停服规则》页也只讲配额套餐 [74][121]。
8. **云开发 MySQL 停止新开通，是否也影响微信云托管的 MySQL**：腾讯云文档写 2026-10-20 起停止新开通 [76]，但云托管定价页仍列着 MySQL 价格 [79]。
9. **分包总上限何时从 20M 调到 30M**：没找到官方公告。社区推测是 2024 年（第三方说法，未核实），不影响现行数字。
10. **开发者工具对 Windows 7 的说法前后矛盾**（已基本澄清）：下载页称"Windows 仅支持 Windows 7 及以上"，但官方版本配置把 1.05 系列标为"支持 Windows 7 的最后一个版本系列"（原则上只修重大 Bug），Stable、RC、Nightly 都"从 1.06 开始不支持Windows7"[33]。也就是说 Windows 7 只能停在 1.05，用不了现行的 2.02。
11. **框架性能对比**：没找到微信官方或中立机构的横向测评数据，本章引用的都是各框架的自述 [50][54][57]。
12. **静音自动播放算不算违规**：运营规范 2.12 只写"禁止多媒体自动播放"，《常见拒绝情形》3.5.2 也是同样措辞，都没区分是否静音 [1][2]。建议默认不自动播放，或先咨询官方。
13. **Donut 专业版的正式收费标准**：尚未公布 [62]（2026-11-02 复核，专业版页面仍只写公测期间已上架应用可免费升级，没有价格，也没有公测结束时间）。
14. **小程序 AI 开发模式的提审开放时间，以及对交易类小程序的具体要求**：官方写"另行通知"[112]；截至 2026-11-02，更新日志最新一条（2026-10-29）仍没有开放提审的记录 [114]。
